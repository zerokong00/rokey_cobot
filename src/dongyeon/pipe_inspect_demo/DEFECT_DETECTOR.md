# defect_detector 노드 설명서

## 1. 개요

`defect_detector.py`는 Isaac Sim의 배관 내부 카메라 영상에서 균열과 구멍처럼
주변 배관 벽보다 어두운 영역을 찾는 ROS 2 노드다.

이 노드는 결함의 종류를 분류하지 않는다. 영상에서 결함으로 의심되는 어두운
영역을 찾고, 여러 프레임에서 연속으로 관찰됐을 때 최종 결함으로 확정한다.

소스 파일:

```text
pipe_inspect_demo/defect_detector.py
```

노드 이름:

```text
defect_detector
```

## 2. 전체 처리 흐름

```text
/rgb 영상 수신
    ↓
ROS Image를 RGB numpy 배열로 변환
    ↓
초기 무결함 영상으로 밝기·노이즈 캘리브레이션
    ↓
배관 벽에 해당하는 고리형(annulus) ROI 생성
    ↓
밝기 임계값보다 어두운 픽셀 추출
    ↓
연결된 blob의 면적과 위치 검사
    ↓
연속 프레임 검증
    ↓
결함 유무·상세 정보·디버그 영상 발행
```

## 3. 입출력 토픽

### 입력

| 토픽 | 메시지 형식 | 설명 |
|---|---|---|
| `/rgb` | `sensor_msgs/Image` | Isaac Sim 전방 카메라 RGB 영상 |

지원하는 영상 인코딩은 다음과 같다.

- `rgb8`
- `bgr8`
- `rgba8`
- `bgra8`
- `mono8`

ROS Image의 한 행에 패딩이 포함된 경우를 고려해 `msg.step` 기준으로 영상을
변환한다. 지원하지 않는 인코딩이나 잘못된 영상 크기는 경고를 출력하고 해당
프레임을 건너뛴다.

### 출력

| 토픽 | 메시지 형식 | 설명 |
|---|---|---|
| `/defect_detected` | `std_msgs/Bool` | 연속 프레임 검증을 통과한 결함 유무 |
| `/defect_info` | `std_msgs/Float32MultiArray` | 현재 프레임의 결함 후보 상세 정보 |
| `/defect/debug_image` | `sensor_msgs/Image` | ROI와 검출 상자가 표시된 RGB 영상 |

`/defect_info` 배열의 순서는 다음과 같다.

```text
[confidence, center_x, center_y, area_px, threshold]
```

| 인덱스 | 값 | 설명 |
|---:|---|---|
| 0 | `confidence` | blob 면적을 이용한 0~1 범위의 단순 신뢰도 |
| 1 | `center_x` | 검출 blob 중심의 영상 X 좌표 |
| 2 | `center_y` | 검출 blob 중심의 영상 Y 좌표 |
| 3 | `area_px` | 검출 blob 면적(픽셀 수) |
| 4 | `threshold` | 현재 사용 중인 밝기 임계값 |

후보가 없는 프레임은 다음 값을 발행한다.

```text
[0.0, -1.0, -1.0, 0.0, threshold]
```

`confidence`는 학습 모델의 확률이 아니다. 최소 검출 면적 대비 현재 blob 크기를
표현한 휴리스틱 값이므로 성능 평가용 확률로 해석하면 안 된다.

## 4. 캘리브레이션

노드가 시작되면 기본 12프레임 동안 밝기와 영상 노이즈를 측정한다.

캘리브레이션 과정은 다음과 같다.

1. 고리형 ROI 안의 밝기 중앙값을 프레임별로 측정한다.
2. 임시 밝기 임계값으로 어두운 blob을 구한다.
3. 캘리브레이션 영상에서 나타난 가장 큰 노이즈 blob을 기록한다.
4. 전체 프레임의 밝기 중앙값으로 최종 밝기 임계값을 계산한다.
5. 고정 최소 면적과 측정된 노이즈 면적 중 더 큰 값을 최종 최소 면적으로 사용한다.

계산식은 다음과 같다.

```text
밝기 임계값 = 배관 벽 밝기 중앙값 × dark_ratio

최소 blob 면적 = max(
    min_area,
    noise_area_scale × 캘리브레이션 최대 노이즈 면적
)
```

캘리브레이션 프레임에는 결함이 없는 정상 배관 벽이 보여야 한다. 시작부터 결함이
보이면 결함 영역이 배경 노이즈에 포함되어 실제 검출이 어려워질 수 있다.

ROI 밝기 중앙값이 5/255 미만이면 조명 문제로 판단하고 캘리브레이션을 다시
시작한다. 실행 중 영상 해상도가 바뀌어도 ROI를 다시 만들고 캘리브레이션을
재시작한다.

## 5. 고리형 ROI

전방 카메라에서 영상 중앙은 배관의 먼 쪽 또는 출구 방향이다. 이 영역은 실제
결함이 없어도 어둡게 보일 수 있기 때문에 검출에서 제외한다.

기본 ROI 범위는 영상 중심으로부터 정규화 반경 `0.45~0.92`이다.

```text
영상 중심
  0.00 ~ 0.45 : 먼 배관 암부이므로 제외
  0.45 ~ 0.92 : 가까운 배관 벽, 결함 검사 영역
  0.92 이후   : 영상 가장자리이므로 제외
```

고리 안쪽 경계에 붙은 어두운 blob도 중앙 암부가 ROI까지 번진 것으로 보고
제외한다.

## 6. 결함 후보 검출

RGB 영상을 회색조로 바꾼 뒤 다음 조건을 만족하는 픽셀을 어두운 픽셀로 판단한다.

```text
gray < threshold
```

어두운 픽셀에 `connectedComponentsWithStats()`를 적용해 연결된 blob을 구한다.
각 blob은 다음 조건을 통과해야 한다.

- 면적이 캘리브레이션으로 정한 최소 면적 이상일 것
- 고리형 ROI 안쪽 경계에 붙어 있지 않을 것

조건을 만족하는 blob이 여러 개라면 면적이 가장 큰 하나를 현재 프레임의 결함
후보로 선택한다.

## 7. 연속 프레임 안정화

한 프레임의 반사나 렌더링 노이즈가 바로 결함으로 보고되지 않도록 연속 프레임
검증을 사용한다.

- 기본적으로 후보가 3프레임 연속 검출되면 `/defect_detected=true`
- 결함 확정 후 후보가 3프레임 연속 사라지면 `/defect_detected=false`

`/defect_info`는 현재 프레임의 후보 정보를 나타내고, `/defect_detected`는 연속
프레임 검증을 통과한 안정화 상태를 나타낸다. 따라서 결함 후보가 처음 나타난
1~2프레임 동안은 상세 정보가 있어도 `defect_detected`는 `false`일 수 있다.

## 8. ROS 파라미터

| 파라미터 | 기본값 | 설명 |
|---|---:|---|
| `image_topic` | `/rgb` | 입력 영상 토픽 |
| `detected_topic` | `/defect_detected` | 결함 유무 출력 토픽 |
| `info_topic` | `/defect_info` | 상세 정보 출력 토픽 |
| `debug_topic` | `/defect/debug_image` | 디버그 영상 출력 토픽 |
| `calibration_frames` | `12` | 초기 캘리브레이션 프레임 수 |
| `dark_ratio` | `0.45` | 배관 벽 밝기에 곱하는 어두움 임계 비율 |
| `annulus_inner` | `0.45` | 고리형 ROI 내부 반경 |
| `annulus_outer` | `0.92` | 고리형 ROI 외부 반경 |
| `min_area` | `40` | blob의 고정 최소 면적(px) |
| `noise_area_scale` | `2.0` | 캘리브레이션 노이즈 면적 배수 |
| `confirm_frames` | `3` | 결함 확정에 필요한 연속 프레임 수 |
| `release_frames` | `3` | 결함 해제에 필요한 연속 미검출 프레임 수 |
| `publish_debug` | `true` | 디버그 영상 발행 여부 |

## 9. 빌드와 실행

워크스페이스의 `src` 폴더가 들어 있는 디렉터리에서 빌드한다.

```bash
cd ~/cobot3_ws/rokey_cobot
colcon build --packages-select pipe_inspect_demo
source install/setup.bash
```

기본 설정으로 실행한다.

```bash
ros2 run pipe_inspect_demo defect_detector
```

파라미터를 변경해 실행하는 예시는 다음과 같다.

```bash
ros2 run pipe_inspect_demo defect_detector --ros-args \
  -p calibration_frames:=20 \
  -p min_area:=60 \
  -p confirm_frames:=4 \
  -p release_frames:=4
```

입력 토픽 이름이 다르면 다음처럼 변경한다.

```bash
ros2 run pipe_inspect_demo defect_detector --ros-args \
  -p image_topic:=/camera/rgb
```

## 10. 결과 확인

토픽 존재 여부와 발행 주기를 확인한다.

```bash
ros2 topic list
ros2 topic hz /defect_detected
ros2 topic hz /defect_info
```

결함 결과를 터미널에서 확인한다.

```bash
ros2 topic echo /defect_detected
ros2 topic echo /defect_info
```

디버그 영상을 확인한다.

```bash
ros2 run rqt_image_view rqt_image_view /defect/debug_image
```

디버그 영상 표시는 다음과 같다.

- 반투명 초록색: 검사 대상 고리형 ROI
- 주황색 상자: 현재 프레임 후보, 아직 연속 검증 전
- 빨간색 상자와 `DEFECT`: 연속 프레임 검증을 통과한 결함
- `CLEAR`: 안정화된 결함 없음 상태

## 11. 파라미터 조정 기준

오탐이 많을 때:

- `min_area`를 높인다.
- `noise_area_scale`을 높인다.
- `confirm_frames`를 늘린다.
- 조명 반사 영역이 ROI 가장자리에 있다면 `annulus_inner` 또는
  `annulus_outer`를 조정한다.

실제 결함을 놓칠 때:

- `min_area`를 낮춘다.
- `dark_ratio`를 높여 더 많은 어두운 픽셀을 포함한다.
- `confirm_frames`를 줄인다.
- 결함이 ROI 밖에 나타나는지 디버그 영상으로 확인한다.

`dark_ratio`를 너무 높이면 정상 배관 벽까지 결함으로 잡힐 수 있고, 너무 낮추면
매우 어두운 결함만 검출된다. 반드시 실제 Isaac Sim 프레임과 기록된 정답을
사용해 조정해야 한다.

## 12. 현재 한계

- 어두운 영역을 찾는 방식이므로 균열과 구멍의 종류를 구분하지 못한다.
- 그림자, 오염, 물기, 관 이음매가 어두우면 결함으로 오인할 수 있다.
- 캘리브레이션 중에는 정상 배관 벽만 보여야 한다.
- `/defect_info`의 신뢰도는 통계적으로 보정된 확률이 아니다.
- RGB 영상 좌표만 제공하므로 실제 배관상의 3차원 위치는 알 수 없다.
- 하나의 프레임에서 여러 결함이 보여도 가장 큰 후보 하나만 발행한다.

다음 단계에서는 `/depth`와 카메라 내부 파라미터를 결합해 결함의 3차원 위치를
계산하고, 로봇 오도메트리와 함께 배관 진입점 기준 위치로 변환할 필요가 있다.
결함 종류 분류가 필요하면 형상 특징 또는 학습 모델을 별도 단계로 추가하는 것이
좋다.

## 13. 문제 해결

### 영상이 들어오지 않는 경우

```bash
ros2 topic hz /rgb
ros2 run pipe_inspect_demo camera_check
```

Isaac Sim이 GUI 및 Play 상태인지, 양쪽 PC의 `ROS_DOMAIN_ID`가 같은지 확인한다.

### 캘리브레이션이 반복되는 경우

로그에 밝기 오류가 표시되면 배관 내부 조명을 확인한다. 평균 밝기가 너무 낮으면
노드는 잘못된 임계값을 확정하지 않고 캘리브레이션을 다시 시작한다.

### 모든 프레임에서 결함이 검출되는 경우

- 캘리브레이션 영상에 결함이 있었는지 확인한다.
- 디버그 영상에서 중앙 암부가 ROI에 포함되는지 확인한다.
- `min_area`와 `noise_area_scale`을 높인다.
- `dark_ratio`를 낮춘다.

### 작은 결함이 검출되지 않는 경우

- `min_area`를 낮춘다.
- `noise_area_scale`을 낮춘다.
- 카메라 해상도와 조명을 높인다.
- 결함이 고리형 ROI 안에 나타나는지 확인한다.

### P1. 전역 밝기 임계값을 국소 대비 방식으로 개선

현재 방식은 배관 벽 전체 밝기 중앙값에 `dark_ratio`를 곱해 하나의 임계값을
사용한다. 관 한쪽이 그림자로 어두워지면 정상 영역 전체가 결함으로 검출될 수 있다.

- [ ] 큰 Gaussian blur 또는 morphology closing으로 배경 밝기 영상을 생성한다.
- [ ] `배경 밝기 - 원본 밝기`로 국소 어두움 차이를 계산한다.
- [ ] 국소 대비 임계값을 ROS 파라미터로 제공한다.
- [ ] 기존 전역 임계 방식과 국소 대비 방식을 선택할 수 있게 한다.
- [ ] 두 방식의 precision과 recall을 동일 시나리오에서 비교한다.
- [ ] 배관의 한쪽만 어두운 조명 조건에서 오탐이 감소하는지 확인한다.
- [ ] CLAHE 적용 여부를 비교하고 과도한 노이즈 증폭 여부를 확인한다.

국소 대비 방식의 기본 형태:

```python
background = cv2.GaussianBlur(gray, (0, 0), sigmaX=15)
dark_difference = background.astype(np.float32) - gray.astype(np.float32)
defect_mask = (dark_difference > local_threshold) & annulus
```
